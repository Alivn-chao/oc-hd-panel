# alpha7：RF、EU、OC 与 AE 供电

- 支持 RF 线缆直接输入。
- 支持 IC2 EU 直接输入（默认 EV 接收等级，可用 power.euSinkTier 调整）。
- 支持 OC 网络供电：普通 OC 线缆连接屏幕与带能量的电脑、电容或能量转换器。屏幕使用 OC 的 Connector API 实际扣能量。
- 支持 AE2 网络供电：ME 线缆接屏幕非正面任意一块即可，不要求频道，也不额外收待机费；从网络实际提取 AE 能量。
- 仍支持「AE/EU/RF → OC 能量转换器 → OC 线缆 → 屏幕」。
- 换算读取 OpenComputers 的 power.value 配置，而非硬编码比例。按 OC 默认配置 1 OC = 10 RF = 2.5 EU = 5 AE，因此每块满亮度 16 RF/t 等效于 1.6 OC/t、4 EU/t 或 8 AE/t。
- 优先使用屏幕已有 RF 等效缓存，不足时尝试 OC 网络，再尝试连接屏幕墙的 AE 网络。外部电不足时不消耗已有缓存的零头；AE 直接供电仅提取当前需要的缺口，不会为了填满大缓存而瞬间抽空 ME 网络。
- 原有开关、亮度、1080p 和 alpha6 刷新管线保留；alpha6 网页运行时仍兼容。

辉光页面可通过 `defi-yield-page-v1` 标签的安装器安装；离线复制到存档的 OC 硬盘后，运行 `lua /home/ochd_defi_yield.lua` 即可。

以下是 alpha6 的基础说明；其中 RF 储能与耗电表示统一等效单位，alpha7 已补充上述多能源接口。

# alpha6：刷新、RF 供电与屏幕设置

基于 `v0.4.0-alpha5-html`，保持 1920×1080 纹理、1280×720 Lua 逻辑坐标，以及原有网页包和 Lua 接口。源码与测试包见 `v0.4.0-alpha7-html` 预发布版本。

## 安装

退出游戏和服务器，移除旧 OCHD JAR。服务端使用 `oc-hd-panel-0.4.0-alpha7-html.jar`；Windows x64 客户端将 `ochd-html-client-win-x64.zip` 解压到游戏目录，同时更新 JAR 和 `ochd-web-runtime/host.jar`。不要同时保留旧 JAR。沿用 alpha5 的 Lua、页面包和 OpenJFX 库，无需重新安装示例。

## 供电与操作

- 屏幕只有在开关开启且 RF 充足时显示画面；新旧存档的空缓存都需要先供电。
- 使用兼容 CoFH RF 接口的导线，从任意一块面板的侧面、顶部、底部或背面输入 RF。正面是显示面，不接收 RF。GTNH 实例已包含 CoFHCore；模组不随包分发该依赖。
- 一处接线可给整面已拼接的墙充电和供电。电量实际保存在各个方块中，拼接、拆分、区块卸载不会复制电量。拆除方块会失去该块中剩余的 RF。
- 右键正面打开页面；右键侧面或背面打开整面墙的设置。屏幕无电或关闭时，正面也可进入设置。
- 设置页可切换开关、拖动亮度滑块（10%–100%），释放滑块时自动保存。设置同步给服务器并写入存档，整面墙共用。
- 世界画面和交互页面同时应用亮度；外框、控制页不调暗，以便恢复设置。关闭或断电时停止网页运行时，禁止页面操作；重新供电后由已有页面包和最新 OC 数据恢复。屏幕开关不会停止 Lua 自动化控制器。
- 距离超过 8 格、无方块编辑权限或被当前 OC 电脑权限拒绝时，服务器不接受设置。

默认每块缓存 **100,000 RF**，单次输入上限 **4,096 RF**，满亮度耗电 **16 RF/t/块**。每块耗电为 `ceil(16 × 亮度百分比 / 100)`；例如一面 5×3 墙满亮度为 240 RF/t，50% 为 120 RF/t，10% 为 30 RF/t。整墙电量不足以支付当前 tick 时不扣除部分电量、直接熄屏。关闭时不耗电，仍可充电。

服务端 `config/ochdpanel.cfg` 的 `power` 分组可改容量、输入上限和满亮度耗电，重启生效。亮度与开关属于存档设置，不写入全局配置。

## 刷新管线

alpha5 由游戏线程轮询下一帧，存在浏览器截图完成、游戏下一次绘制、请求下一帧的额外等待。alpha6 在浏览器侧连续产帧，交互时目标 60 FPS，世界观看目标 30 FPS；双像素缓冲限制内存和编码任务数量。缓冲占满时跳过截图，游戏端只使用最新完整帧，不累积旧画面。

静止画面不重复编码和传输；不可见超过约 0.5 秒暂停连续截图，15 秒不使用则关闭运行时；屏幕断电或关闭后直接关闭运行时。画布分辨率和无损编码不变。

顶部缩放、全屏和返回页签沿用原位置与操作方式，移除白底，使用与金属外框一致的深蓝灰、浅蓝文字和青色高亮。

同一台 Windows 电脑、Java 21、Direct3D 优先、同一张持续动画 1080p Canvas 页面，预热 2 秒后计时 4 秒：

| 方式 | 收到完整帧的平均速率 |
| --- | ---: |
| 官方 alpha5 运行时、模拟游戏 60 Hz 轮询 | 17.75 FPS |
| alpha6 连续产帧、双缓冲 | 47.25 FPS |

这些是浏览器进程到本地读取端的结果，不包含 Minecraft 纹理上传、游戏渲染或光影开销，不能当作游戏内 FPS 保证。`tools/web/benchmark_stream.py --baseline 基准host.jar` 可复测。**OC `publish` 的数据节流仍为每 10 个服务器 tick 一次**；页面动画刷新与机器数据采样是两个不同频率。

## 验证范围

Java 测试覆盖 RF 模拟输入、共享充电、整墙欠压不扣部分电、亮度耗电、容量边界及拆分重组守恒；同时保留原有布局、绑定、网页协议、输入队列、帧编码和视口测试。

真实 Windows WebKit 测试覆盖输入/粘贴、滑块、缩放、输入洪峰后的点击、OC 数据/事件/回执、连续帧、静止帧抑制、暂停与恢复。Lua 示例与绑定模拟通过。

尚未进行 GTNH 实机验收：需验证 RF 导线实际连接、四向屏幕的侧面菜单、多人权限、真实供电与断电、存档重启、跨区块拼接，以及开启光影后的实际帧率。未替换现有游戏实例的 mods 或配置。

源码构建需在 `libs/` 放入原版 OpenComputers JAR、作为保留基准的原 alpha4 JAR，以及仅编译使用的 `CoFHCore.jar`、`IC2.jar`、`AE2.jar`（可从实例复制；不打入发行物）。常规执行 Gradle `test reobfJar`、`tools/package_alpha4_bindings.py`、`tools/web/build_runtime.py` 和 `tools/web/package_release.py`。
